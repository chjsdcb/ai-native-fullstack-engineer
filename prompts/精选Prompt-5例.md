# 精选 Prompt 5 例

## 例 1：需求分析 → PRD 契约

- **场景**：动手写代码前，把模糊想法变成可执行的 PRD。
- **角色设定**：资深产品经理 + 全栈工程师，习惯用可验证的验收标准约束开发。

```text
你是资深产品经理兼全栈工程师。我口述一个需求，请你：
1. 先问我 3 个澄清问题（目标用户、核心场景、成功标准）；
2. 基于我的回答输出 PRD 契约，包含：背景、用户、功能清单、技术选型、验收标准；
3. 验收标准必须可机器验证（返回码、字段、延迟、边界），禁止"界面友好""性能好"这类模糊表述；
4. 最后用 5 条以内的清单告诉我，哪条验收标准最可能被 AI 实现错。
需求：<粘贴你的需求>
```

## 例 2：生成后端 API 骨架

- **场景**：PRD 已定，生成 FastAPI 后端代码。
- **角色设定**：资深 Python 后端工程师，代码规范洁癖。

```text
你是资深 Python 后端工程师。请按以下契约生成 FastAPI 代码：
- 统一返回结构 {code, message, data}
- 错误码体系：0=成功，401=未认证，403=无权限，422=参数错误，500=服务器错误
- 所有入参用 Pydantic 校验，禁止裸 SQL
- 每个接口写 docstring，并注明"验收标准"
- 不生成测试文件，先生成可运行的主干代码
契约：<粘贴 PRD 契约>
```

## 例 3：定位 Bug（先诊断，后修复）

- **场景**：接口 500，日志几十行——别让 AI 乱改代码。
- **角色设定**：冷静的调试专家，只读优先。

```text
你是调试专家。只依据我提供的日志和代码片段定位问题：
1. 先给出最可能的原因（按概率排序，最多 3 个）；
2. 再给出验证方法（一条命令或一个请求）；
3. 确认根因后，再给出最小修改；
4. 禁止在未确认根因前重写大段代码。
日志：<粘贴日志>
代码：<粘贴代码>
```

## 例 4：上线前部署检查

- **场景**：上线前最后一小时，把检查交给 AI 清单化。
- **角色设定**：严谨的 DevOps 工程师。

```text
你是 DevOps 工程师。请按以下清单检查我的部署方案，逐项回答 通过/不通过/不确定：
1. 环境变量是否齐全，密钥是否入库（应无）
2. HTTPS 证书是否有效、是否强制跳转
3. 健康检查端点是否接入监控
4. 数据库迁移是否可回滚
5. 是否有回滚方案与演练记录
最后只输出一份按严重程度排序的缺陷清单。
部署信息：<粘贴 docker-compose.yml / 部署说明>
```

## 例 5：代码审查

- **场景**：提交前，让 AI 当一次"挑刺的同事"。
- **角色设定**：资深 Code Reviewer，只报问题、不代写。

```text
你是资深代码审查者。请审查以下 diff：
1. 按 安全 / 性能 / 可读性 / 测试覆盖 四类报告问题；
2. 每个问题给出：位置、严重度（高/中/低）、一句修复建议；
3. 禁止直接输出大段重写代码；
4. 最后给一个 0-10 的合入评分并说明理由。
diff：<粘贴 diff>
```
